**AI PULSE — SCRIPT MAÎTRE DE LA PRÉSENTATION INTERACTIVE**

**1. RÔLE**

Tu es un **designer produit, UX/UI designer, développeur web et concepteur pédagogique spécialisé en IA**.

Ta mission est de créer pour **Removall Carbon** une expérience web interne à mi-chemin entre :

- une présentation PowerPoint      premium ;
- un questionnaire interactif      en direct ;
- un dashboard de résultats ;
- une formation courte à      l’intelligence artificielle ;
- une démonstration concrète      des capacités de l’IA.

L’expérience doit pouvoir **remplacer complètement un PowerPoint** pendant un atelier.

Le site possède deux interfaces synchronisées :

**Mode Présentateur**

- utilisé sur ordinateur ;
- affiché sur vidéoprojecteur /      grand écran ;
- format principal 16:9 ;
- navigation slide par slide ;
- ouverture et fermeture des      sondages ;
- affichage ou masquage des      résultats ;
- contrôle du timer ;
- résultats mis à jour en      direct.

**Mode Participant**

- utilisé principalement sur      smartphone ;
- accès par QR code ;
- le participant voit      uniquement l’interaction actuellement ouverte ;
- aucune navigation dans la      présentation ;
- réponses anonymes par défaut.

L’expérience doit donner le sentiment :

**« Nous ne sommes pas simplement en train de regarder une présentation sur l’IA : nous sommes en train d’utiliser une expérience construite avec l’IA. »**

**2. OBJECTIF**

L’atelier doit remplir quatre objectifs.

**1 — Mesurer**

Comprendre :

- à quelle fréquence les      collaborateurs utilisent déjà l’IA ;
- combien de temps ils pensent      gagner grâce à l’IA ;
- leur appétit pour davantage      d’automatisation ;
- les tâches qu’ils souhaitent      prioritairement automatiser.

**2 — Expliquer**

Faire comprendre simplement :

- comment fonctionne une IA ;
- comment un modèle utilise un      contexte ;
- comment fonctionne la      recherche documentaire ;
- pourquoi une IA peut manquer      une information ;
- pourquoi il faut vérifier les      résultats.

**3 — Former**

Donner quelques règles immédiatement utilisables :

- mieux structurer un prompt ;
- choisir le bon type d’outil      IA selon le besoin ;
- comprendre la différence      entre chat, espace de travail, chatbot documentaire, agent, workflow, etc.

**4 — Faire émerger des priorités**

À la fin :

- proposer 8 cas d’usage ;
- permettre à chaque      collaborateur d’en sélectionner un ;
- faire émerger les **3 sujets les      plus sélectionnés**      ;
- les présenter comme **3 pistes à      approfondir**, et      non comme un podium.

**Question participant**

**Dans un assistant documentaire basé sur la recherche de passages, cette information sera-t-elle forcément retrouvée ?**

Options :

**Oui, forcément**

**Non, pas forcément**

**Résultat**

Petit diagramme circulaire.

**Révélation**

**Non, pas forcément.**

Explication :

Un système RAG peut :

1. découper le document ;
2. chercher les passages qu’il      considère pertinents ;
3. sélectionner seulement      quelques blocs ;
4. transmettre uniquement ces      blocs au modèle.

Si le passage contenant l’information importante n’est pas sélectionné :

**le modèle peut ne jamais recevoir cette information.**

Nuance importante :

Ne pas dire :

**« L’IA ne lit jamais tout le document. »**

Dire :

**« Selon l’architecture utilisée, le document entier peut être transmis au modèle ou seulement certains passages. »**

Ajouter éventuellement :

**Lost in the Middle — 2023**

La position d’une information dans un contexte long peut également influencer la performance.

Prends un exemple qui peut se rapporter aux crédit carbone (un document un poil plus long)

- investigation.

- travail continu.

**GPT**

Pour :

- besoin récurrent ;
- mêmes instructions ;
- même format de réponse ;

- CHATBOT DOCUMENTAIRE

**AGENT**

un besoin nécessitant plusieurs étapes.

**chercher → analyser → agir → vérifier.**

**MEETING NOTES**

Pour :

- transcription ;
- compte rendu ;
- décisions ;
- responsables ;
- deadlines.

**WORKFLOW / AUTOMATISATION**

Pour :

un processus répétitif et suffisamment stable.

**nouveau document → analyse → extraction → création d’un fichier → notification**

**8. ÉLÉMENTS RETIRÉS PAR RAPPORT AU BRIEF INITIAL**

Ces fonctionnalités faisaient partie des premières idées, mais ont été retirées dans les arbitrages suivants :

**Training Folder séparé**

→ fusionné avec la slide « Quel outil IA pour quel besoin ? ».

**GPT spécialisés par métier**

→ supprimés au profit d’une présentation par type de besoin.

**Mur “Si tu pouvais automatiser UNE chose demain”**

→ supprimé car redondant avec les questions précédentes.

**Regroupement IA des idées**

→ supprimé avec le mur d’idées.

**Vote à trois jetons sur les idées**

→ remplacé par un vote simple sur 8 propositions.

**Mini quiz**

→ supprimé.

La question sur la recherche documentaire reste interactive, mais elle est considérée comme **une démonstration pédagogique**, pas comme un mini-quiz.

**9. PRINCIPES À NE PAS PERDRE DANS LES PROCHAINES MODIFICATIONS**

**Le site doit toujours ressembler davantage à une présentation qu’à un formulaire.**

**Les graphiques doivent toujours être calculés à partir des vraies réponses.**

**Les participants restent anonymes.**

**Le présentateur contrôle le rythme.**

**Les slides pédagogiques doivent rester simples à comprendre à l’oral.**

**Ne pas faire passer pour une certitude scientifique ce qui est seulement une estimation ou une perception.**

**Toujours distinguer :**

**résultats de notre salle / étude scientifique / déclaration utilisateur / estimation économique.**

**Le niveau de détail peut être élevé dans le fond, mais l’écran doit rester visuellement simple.**

**NE PAS AJOUTER D'autres Slide que celles abordés**
